# Architecture

Silicon Quest uses React/TypeScript for its interface and Tauri/Rust for the desktop boundary. SQLite stores progress, notes, quiz attempts, XP events, achievements, imported PDF data, private artwork, page positions, bookmarks, manual chapter indexes, activity days, focus checkpoints and review schedules/events locally. The Tauri application creates its database under the platform application-data directory, outside the source tree.

## Curriculum boundary

The provided roadmap is the source of truth. `curriculum/build_seed.py` authors stable IDs and derives two JSON artifacts:

- `data.json`: complete curriculum plus answer keys and explanations, embedded by the Rust store.
- `public-data.json`: curriculum and public questions with answer keys/explanations removed, imported by `data.ts` for the interface.

There are nine books, seven roadmap phases, four portfolio projects and four credential groups. Topic modules are explicitly provisional groupings. They assert neither exact textbook chapter numbering nor a verified table of contents. One runtime-design topic has no book assignment because its source is the roadmap itself.

The source roadmap discusses unverified prices, board support and tool versions. They remain labeled planning assumptions in the seed; the application does not turn them into live recommendations.

## Local persistence and grading

Tauri commands expose dashboard reads, topic-status changes, note updates, quiz retrieval/submission, local PDF import/read, revision-bound reader state, focus tracking and review summaries. SQLite migrations version the schema. The backend validates stable topic/book IDs and quiz answers, grades against the bundled key, and persists results. Self-reported reading, latest-check results and repeated-review mastery remain separate. The legacy `topic_progress.mastery` field describes the latest check result; review schedule stage and `masteredCount` describe repeated qualifying recall.

XP is an event ledger rather than a mutable client total. Quiz attempt identifiers support safe retries, and unique award keys prevent repeat passing attempts from farming the same reward. Changes that span attempts, mastery and XP use a transaction. UI progress always needs to be reloaded from the authoritative store after mutation.

PDF import records the local document against a known book. Schema migration 2 preserves existing documents/progress and adds opaque document revisions, page positions and labeled page bookmarks. Writes validate the current revision in the same transaction as the mutation, rejecting stale windows after replacement. Reimporting current identical bytes preserves state; different bytes create a fresh revision. Older revision metadata stays in SQLite but has no restore interface. PDF.js checks actual page bounds; the backend also enforces integer bounds. Reader actions award no XP and claim no mastery. Text extraction or automatic chapter mapping must not silently replace the provisional curriculum; future mappings need explicit evidence and user review. There is no cloud account or remote sync architecture in this version.

Migration 3 adds [focus sessions](docs/FOCUS.md): backend monotonic checkpoints, an exclusive process ownership lock and recovery at the last saved checkpoint without offline credit. Timer actions do not change XP, latest-check results or review evidence.

Migration 4 adds [scheduled review](docs/REVIEW.md), replaying all existing grades in chronological order while preserving raw history and earned rewards. New scheduling events, grades, current results and first-pass XP share a transaction. Three qualifying successes are required for repeated-review mastery; early passes remain practice. The interface prevents stale queue requests from replacing a newer quiz-returned summary.

Migration 5 adds application/workspace identity and [backup/restore](docs/BACKUP.md). Native Rust dialogs choose paths; JavaScript supplies only opaque preview tokens. Validation and legacy migration occur in private staging. A shared writer/startup gate and exclusive restore gate span safety capture and atomic same-file replacement. Fresh candidate epochs reject stale writers; a successful restore fences the process until restart. A root boundary unmounts learner state/providers and supports status recovery when a restore response is uncertain. Backups are plain local SQLite files containing PDF BLOBs, with no encryption or cloud-transfer service.

Migration 6 adds [project evidence tracking](docs/PROJECTS.md): four canonical plans, 35 milestone definitions, 75 child tasks, versioned saved state and immutable self-review snapshots. Completion requires saved evidence, explicit acknowledgement and an exit review after required work; no source, reading, timer or quiz activity fabricates project progress. Definition changes invalidate readiness/completion as needed, and optional stretches remain outside baseline completion. Project mutations and backups use the same restore gates/epochs as other learning data.

Migration 7 adds [personal course/credential tracking](docs/CREDENTIALS.md) for four stable roadmap identities with explicit taxonomy, calendar targets, notes/plain references and immutable report snapshots. Completion is self-reported and changes no XP, quiz mastery or project evidence. Metadata updates version records without revoking personal reports. Saved state/history round-trip in backups; course drafts participate in restore warnings and root-provider teardown.

Migration 8 adds [manual chapter indexes](docs/CHAPTERS.md). Stable user-created chapter IDs preserve notes/status across title and order edits. Optional PDF page ranges bind to a document revision; replacing a PDF preserves chapter records but disables stale page links. Optimistic versions reject stale saves, and writes share the backup gate/epoch protections. Per-book drafts live in the application root and participate in backup/restore warnings. Chapters remain separate from provisional roadmap topics and change neither XP nor quiz/review mastery.

Migration 9 adds [private book/course artwork](docs/ARTWORK.md) keyed by known curriculum identity. The native chooser accepts bounded local PNG/JPEG input; Rust decodes, resizes and re-encodes to normalized PNG without retaining source paths or image metadata. Artwork reads return image bytes through IPC, and React displays revocable blob URLs. Imports and resets share the backup gate/epoch safeguards, do not change learning records or activity, and are included in validated backups. No provider image is bundled or downloaded by the app.

Migration 10 adds revision-bound PDF annotations: page notes and text highlights with quoted text and normalized page-relative rectangles. Saves use optimistic versions and replay recognition; deletes retain tombstones. Mutations validate the active PDF revision and workspace epoch under the shared restore gate. Annotations remain private SQLite sidecar data, never changes to PDF bytes, and award no XP or mastery. Backup validation checks identities, versions, timestamps, size/count limits and finite bounded highlight geometry. Session drafts are retained by book/revision and included in backup/restore warnings.

Early schema-10 installations had page notes without highlight columns. Migration 11 transactionally normalizes both historical schema-10 layouts, preserving note identities, versions, timestamps, deleted history and any existing highlight anchors. It also permits empty note bodies for quote-only highlights. Backup inspection accepts the exact historical layouts, validates their records before migration and migrates only the private staged copy. Annotation loading has its own readiness state; failure to restore page position/bookmarks does not disable otherwise available annotations. Loading, read errors/retry, browser-only restrictions and existing drafts remain visible while the annotations panel is collapsed.

The continuous PDF.js reader lays out page placeholders and renders canvases/text layers only near the viewport. Visible-page tracking updates saved page position; explicit jumps and zoom retain the current page, with anchoring for newly measured page sizes. A shared scrolling metadata area bounds chapter, bookmark and annotation panels so page controls remain accessible. Selection anchors are normalized against the page surface so highlights follow zoom. Scanned pages need selectable text for highlighting, and selections spanning pages are unsupported. Browser preview cannot save annotations durably.

Fullscreen keeps the reader subtree mounted and restores its scrolling offsets across transitions. Desktop entry uses the current Tauri window with narrowly granted fullscreen permission; browser preview uses the Fullscreen API or a viewport fallback. Exit controls, Escape, native resize/fullscreen state and unmount cleanup restore the surrounding interface. The active reader contains keyboard focus and temporarily makes outside content inert. PDF text anchors intersect the page crop, exclude reader captions and are unavailable while an old zoom's text layer is being replaced. The page surface and highlight overlay clip their contents to the page bounds.

The [activity heatmap](docs/ACTIVITY.md) reads the existing `activity_days` ledger rather than deriving study from navigation or Git history. Qualifying changed reading/notes, new accepted attempts and confirmed focus time insert local calendar days in their mutation transaction. Focus intervals split activity across local midnight while duration rollups keep their documented UTC policy. Dashboard responses supply the authoritative local date and current/longest streaks; UI calendar arithmetic is independent of browser timezone. The interface refreshes on confirmed mutations/checkpoints, window focus and a one-minute interval, preserves confirmed history on refresh failure, and exposes dates through mouse and keyboard inspection.

The interface uses bundled code, system fonts and local PDF.js assets. The graphite palette, compact desktop navigation, visible keyboard focus and reduced-motion overrides add no remote font, image or analytics dependency.

## Publication boundary

Only source, curriculum, lockfiles and documentation belong in Git. `.gitignore` excludes personal material, database files, PDFs, secrets and generated output. Before any push, inspect the staged files, run required checks and confirm no private study data has entered the index.
